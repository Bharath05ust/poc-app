03 / The distinction

Explicit endpoint or discovered capability?

A REST client chooses a known endpoint such as browse books or place an order. An MCP host discovers server capabilities, then can select a tool based on the user's goal. MCP also gives the host a standard way to read context and request reusable prompts.

ToolSearch books or build a reading plan from a goal.
ResourceRead the bookstore catalog with prices and stock.
PromptGet a reusable book-recommendation instruction.

      

      

        
04 / What this demo runs

        
Follow each request to its function.

        
This demo lets you select the operation manually. No model is connected; in an AI application, the host can give tool descriptions to a model and handle its tool choice.

        

          
REST browseGET /api/books?category=Technology → FastAPI validates query parameters → browse_books() filters the catalog → JSON list.

          
REST orderPOST /api/orders with {"book_id":"b101","quantity":2} → create_order() checks stock, decrements it, and returns a receipt.

          
MCP searchHost reads tool schema with tools/list → sends tools/call for search_books → server returns structured book results.

          
MCP planHost calls build_reading_plan with a learning goal → server chooses and orders books → host receives structured steps.

          
Also MCPbookstore://catalog is readable context; book_recommendation is a reusable prompt. MCP complements APIs; it doesn't replace them.
